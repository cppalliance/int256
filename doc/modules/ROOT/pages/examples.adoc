[#examples_cuda]
== Use of the library in a CUDA kernel

The type and most of the free functions are annotated to run on the device, so a kernel can use them the same way host code does.
This example is the minimal shape of a device workload and a good starting template: allocate managed memory so one array serves both host and device, compute one `gcd` per thread, then recompute on the host and compare every element.

.This https://github.com/cppalliance/int256/blob/develop/example/cuda.cu[example] demonstrates computing the GCD of 50000 pairs of `uint256` values in a CUDA kernel over managed memory, and checking every result against the same computation on the host.
====
[source, c++]
----
include::example$cuda.cu[]
----

Output:
----
[Vector operation on 50000 elements]
CUDA kernel launch with 196 blocks of 256 threads
All CPU and GPU computed elements match!
----
====

The block count is `(50000 + 255) / 256`, so every line above is the same on any device.

[#examples_sycl]
== Use of the library in a SYCL kernel

The same workload as the CUDA example above, expressed in SYCL with unified shared memory in place of managed allocations.
