[#release_notes]
= Release Notes
:idprefix: release_notes_

== v1.0.0

Initial release.

=== The type

`boost::int256::uint256` is an unsigned 256-bit integer that is exactly 32 bytes on every platform, trivially copyable, standard layout, and usable in constant expressions from pass:[C++14] onward.
It stores four `std::uint64_t` words with `words[0]` least significant, in the same order on every platform.
The full operator set is provided against `uint256`, against every built-in integer type in either operand order, against the compiler's `pass:[__int128]` and `pass:[unsigned __int128]` where those exist, and against the built-in floating-point types under the usual arithmetic conversions.
See xref:uint256.adoc[uint256] and xref:mixed_type_ops.adoc[Mixed Type Operations].

A signed `int256` is planned for a following release, and will use the same header layout, macro names, and word order.

=== Features by header

* `<boost/int256/int256.hpp>`: the type, the full operator set, `operator<=>` where the standard library has it, and `abs`.
* `<boost/int256/limits.hpp>` and `<boost/int256/climits.hpp>`: `std::numeric_limits<uint256>` (`digits` 256, `digits10` 77, `is_modulo` true) and `BOOST_INT256_UINT256_MAX`.
* `<boost/int256/bit.hpp>`: `has_single_bit`, `countl_zero`, `countl_one`, `countr_zero`, `countr_one`, `bit_width`, `bit_ceil`, `bit_floor`, `rotl`, `rotr`, `popcount`, `byteswap`.
* `<boost/int256/byte_conversions.hpp>`: `to_be`, `from_be`, `to_le`, `from_le`, and the 32-byte array forms `to_be_bytes`, `to_le_bytes`, `to_ne_bytes` with their `from_*` counterparts.
* `<boost/int256/numeric.hpp>`: saturating arithmetic, `saturating_cast`, `gcd`, `lcm`, `midpoint`, and the complete P3724 integer division family with `div_result<T>`.
* `<boost/int256/utilities.hpp>`: `addmod`, `powm`, `ipow`, `isqrt`, the C23 checked operations `ckd_add`, `ckd_sub`, `ckd_mul`, the signedness-safe comparisons `cmp_*`, and `in_range`.
* `<boost/int256/cstdlib.hpp>`: `div` returning `u256div_t`.
* `<boost/int256/iostream.hpp>` and `<boost/int256/string.hpp>`: stream insertion and extraction honoring `dec`, `oct`, `hex`, `showbase`, `uppercase`, and the width and fill manipulators, plus `to_string` and `to_wstring`.
* `<boost/int256/literals.hpp>`: the `_u256` and `_U256` user-defined literals, and `BOOST_INT256_UINT256_C`.
* `<boost/int256/hash.hpp>`: `std::hash<uint256>` and an ADL `hash_value` for Boost.ContainerHash and Boost.Unordered.
* `<boost/int256/format.hpp>` and `<boost/int256/fmt_format.hpp>`: `std::formatter` and `fmt::formatter` specializations supporting the integer presentation types and the fill, align, width, and alternate forms.
* `<boost/int256/charconv.hpp>` (opt-in): `boost::charconv::to_chars` and `from_chars` for bases 2 through 36.
* `<boost/int256/random.hpp>` (opt-in): the traits that let Boost.Random distributions generate `uint256`.

=== Platforms

Tested on Ubuntu (x86_64, x86_32, s390x, aarch64, ARM32v7), macOS (x86_64 and Apple Silicon), Windows (x86_64, x86_32, ARM64), and emulated PPC64LE, with GCC 5 and later, Clang 5 and later, Visual Studio 2017 and later, Intel oneAPI DPC++ 2024.2 and later, and NVCC 12.8 and later.
The type and most functions also run in CUDA and SYCL device code.

=== Extras

* A single amalgamated header, regenerated by CI, at `extra/single_include/boost/int256.hpp`.
* A pass:[C++20] named module: `import boost.int256;`. See xref:config.adoc#build_module[`BOOST_INT256_BUILD_MODULE`].
* Debugger pretty printers for LLDB, GDB, and MSVC. See xref:printer.adoc[Pretty Printers].
* A vcpkg port under `ports/int256`.
* Benchmarks against Boost.Multiprecision. See xref:u256_benchmarks.adoc[Benchmarks].
